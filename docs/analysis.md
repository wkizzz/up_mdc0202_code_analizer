# Анализ предметной области

**Проект:** Static Analyzer (UP 02.02, вариант 9)
**Команда:** Иванов И.И., Петров П.П.

## 1. Предметная область

Инструментальные средства разработки ПО, подкласс «статический анализ кода».
Модуль ищет в Python-проектах нарушения по набору **настраиваемых правил**
и формирует отчёты в **JSON** и **SARIF** для интеграции с IDE и CI.

## 2. Основные фичи

| # | Фича | Описание |
|---|---|---|
| F1 | Конфигурируемые правила | Стандартные + пользовательские (YAML/JSON) |
| F2 | Severity | INFO / MINOR / MAJOR / CRITICAL |
| F3 | Отчёты JSON + SARIF | SARIF 2.1.0 для IDE |
| F4 | Inline-ignore | `# noqa: RULE_ID`, `# analyzer: disable-next-line RULE_ID` |
| F5 | CI-интеграция | Exit 1 при находках CRITICAL, иначе 0 |

## 3. Акторы

| Актор | Цель |
|---|---|
| Разработчик | Проверить свой код локально, подавить ложные срабатывания |
| CI-система | Автоматически блокировать merge при критических находках |
| IDE | Получить SARIF-отчёт и подсветить проблемы в редакторе |

## 4. Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | CLI: `--path`, `--config`, `--format {json,sarif}`, `--output`, `--fail-on {info,minor,major,critical}` |
| FR-2 | Загрузка правил из YAML/JSON (свои + стандартные) |
| FR-3 | Стандартные правила: TODO-маркеры, длинные строки, опасные вызовы (eval, exec, os.system, subprocess shell=True, pickle.loads) |
| FR-4 | Пользовательские правила: id, regex, severity, message |
| FR-5 | Рекурсивный обход `*.py` |
| FR-6 | Парсинг inline-директив `# noqa: RULE_ID` и `# analyzer: disable[-next-line] RULE_ID` |
| FR-7 | Отчёт JSON со списком находок и полями: rule_id, severity, file, line, column, message, ignored |
| FR-8 | Отчёт SARIF 2.1.0 (совместим с VS Code SARIF Viewer) |
| FR-9 | Exit-код: 1, если есть находки с severity ≥ `--fail-on`; иначе 0 |
| FR-10 | `--help` с описанием всех опций |

## 5. Нефункциональные требования (NFR)

| ID | Категория | Требование |
|---|---|---|
| NFR-1 | Производительность | Скан 1000 файлов ≤ 5 секунд на средней машине |
| NFR-2 | Безопасность | Модуль не выполняет анализируемый код |
| NFR-3 | Надёжность | Ошибка чтения одного файла не прерывает скан |
| NFR-4 | Переносимость | Python 3.10+, Windows / Linux / macOS |
| NFR-5 | Сопровождаемость | PEP 8, покрытие тестами ≥ 60 %, pylint score ≥ 8 |
| NFR-6 | Расширяемость | Новое правило добавляется через конфиг без изменения кода |
| NFR-7 | Совместимость | SARIF 2.1.0 (спецификация OASIS) |

## 7. Ограничения и допущения

- Только `*.py` файлы.
- Правила на регулярках (без полноценного AST-парсера) — упрощение в учебных целях.
- В MVP поддерживается SARIF-подмножество: `runs[].results[]` с полями ruleId, level, message, locations.
- Inline-ignore поддерживает 2 синтаксиса: `# noqa: ID` и `# analyzer: disable[-next-line] ID`.

## 8. Глоссарий

| Термин | Определение |
|---|---|
| SARIF | Static Analysis Results Interchange Format, стандарт OASIS для обмена результатами |
| Severity | Уровень важности находки (INFO / MINOR / MAJOR / CRITICAL) |
| Inline-ignore | Комментарий в коде, подавляющий срабатывание правила |
| Rule ID | Уникальный идентификатор правила (например, `SEC001`) |
| MVP | Minimum Viable Product — минимально работающий набор функций |
